# Technical Writing Patterns

## Status
- **Epistemic status**: RESEARCH_ONLY / SOURCE_SUPPORTED
- **Use**: A field guide for engineering Japanese, not a universal rule for every Japanese document.

## 1. Style diversity in technical Japanese
- Technical writing may use plain style, polite style, or mixed registers depending on audience, document type, and internal conventions.
- The project must not claim that technical documentation always avoids `です/ます` or always prefers `である`.
- Instead, style should be treated as context-sensitive and audience-aware.

## 2. Conditional and causal phrasing
- Common patterns include dependency statements, condition statements, and action triggers.
- Examples:
  - `エラーが発生した場合、ログを記録する。`
  - `条件が満たされない場合は処理を中止する。`
- These patterns support L3 engineering semantics but do not impose a single mandatory style.

## 3. AAM mapping
- This file informs engineering semantics around `CONSTRAINT`, `EXPECTATION`, `FLOW`, and `DEVIATION`.
- It should be treated as an analytical pattern library rather than a corpus-validated normative standard.

## 4. Repository note
This module is useful for project documentation and term mapping, but it is not a universal grammar rule for all technical Japanese.
